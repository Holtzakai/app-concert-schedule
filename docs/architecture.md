# 演奏会進行表メーカー — アーキテクチャ設計

## 1. 選定結果

初版は、HTML・CSS・JavaScriptだけで動作する静的1ページアプリとする。サーバー、データベース、外部API、ログインは使用しない。GitHub Pagesではリポジトリをそのまま公開でき、`npm run build` を使う場合は `dist/` を配布できる。

採用理由は次のとおり。

- 進行計算は端末内だけで完結し、出演団体や公演情報を外部へ送信しない。
- PDFは進行表を端末内でA4横のPDFへ直接描画し、ファイルとして保存する。
- Excelは外部ライブラリを読み込まず、ブラウザー内でOOXML形式の `.xlsx` を生成する。
- 計算部分をDOMから分離した純粋関数にし、元Excelとの照合や将来のルール変更を容易にする。
- 端末内の入力保持には `localStorage` のみを使う。

## 2. 元Excelから抽出した仕様

参照ブックには「説明書」「データ」「テンプレ部」「GP」「印刷用」「GP印刷用」の6シートがある。

本番進行の主なルールは次のとおり。

1. 各団体の演奏開始は、直前の演奏開始に演奏時間を足して求める。
2. 休憩は指定時間を確保し、休憩後の最初の演奏には追加の開演猶予（元ブックでは1分または5分）を加える。
3. ステージ袖時刻は演奏開始から団体別の準備時間を引く。
4. チューニング終了はステージ袖から移動時間を引き、開始はさらにチューニング時間を引く。
5. GPは既定で本番の演奏団体だけを逆順に並べる。Web版では本番から独立したGP曲順も保持でき、指定したGP開始時刻から再計算する。
6. 印刷用レイアウトはA4横で、順、団体編成、チューニング開始・終了・部屋、ステージ袖、演奏開始、照明3項目、影アナを表示する。

Web版では「演奏終了」と「次までの間隔」を追加した。元ブックの計算を保ちつつ、転換や余白時間を明示的に調整できるようにするためである。

## 3. 構成

```text
index.html                    画面の骨格
styles.css                   編集画面・A4横印刷レイアウト
src/app.js                   状態管理、画面描画、操作
src/domain/schedule.js       時刻計算（UI非依存）
src/domain/sample.js         初期サンプル
src/domain/project.js        中間データJSONの検証・保存・復元
src/export/pdf.js            A4横PDF生成
src/export/xlsx.js           Excel（OOXML）生成
test/                        計算・Excel生成テスト
scripts/build.mjs            distへの静的ビルド
```

データフローは `入力またはJSON → 状態 → calculateMainSchedule / calculateGpSchedule → 画面・PDF・Excel` の一方向とする。PDFとExcelは同じ計算結果を使うため、表示と出力の時刻がずれない。

## 4. データモデル

公演設定は団体名、タイトル、日付、会場、開場、開演挨拶、最初の演奏、GP開始、チューニング時間、移動時間、用紙方向を持つ。本番の進行項目とは別に、演奏項目IDの並びとしてGP曲順を保持する。

進行項目は以下の3種類。

- `performance`: 団体編成、演奏時間、袖待機、次までの間隔、部屋、照明、影アナ
- `break`: 名称、休憩時間、休憩後の追加猶予、照明、影アナ
- `cue`: 挨拶などの名称、所要時間、次までの間隔、照明、影アナ

時刻は計算時に「当日0時からの分」に正規化する。これにより日付オブジェクトやタイムゾーンに依存せず、日をまたぐ進行も扱える。

## 5. 出力と配布

- PDF: 現在表示している本番またはGP進行表を、選択したA4横またはA4縦のPDFとして直接保存する。縦版は時刻と照明をまとめた専用の7列構成とする。
- Excel: 「本番進行表」「GP進行表」「入力データ」の3シートを含む `.xlsx`。
- JSON: 編集中の公演設定と進行項目を保存し、別端末や後日の編集で復元する。
- GitHub Pages: 同梱のActions設定は `dist/` を自動公開する。ビルドを使わず、リポジトリ直下をPagesの公開元にしても動作する。

## 6. 今後の拡張余地

- JSONによる公演データの受け渡し
- 複数チューニング室の競合チェック
- 当日の遅延を入力したリアルタイム再計算
- 団体名・編成・曲目を分けた詳細入力
- 元Excelの完全な列幅・フォント・罫線への出力差分調整

これらは中核計算と別層に追加でき、サーバーを導入せず拡張可能である。
